# Phase 3：工具化试点实施计划

前置条件：Phase 2 提交 `2cd335c` 已通过托管 CI。Phase 3 分支必须从
`feat/phase-2-memory-governance` 创建，直到该堆叠分支合并后再按同一提交
关系更新目标分支。

## 成功定义

一个试点团队可在 30 分钟内完成部署、自助连接一个真实系统，并用受权限保护的
证据和受控工具完成首项任务。Phase 3 不增加多智能体、图数据库或第二个连接器。

## 0. 试点契约与基线（第 1 周）

1. 选定唯一首发连接器：由已签约/明确试点团队在 Jira、Confluence、Git 中选择一个；
   未确定客户前默认不实现连接器。
2. 定义 5--10 个真实任务、成功判定、数据边界、允许工具、人工审批动作和失败联系人。
3. 记录 Phase 2 基线：首任务时间、任务完成率、工具成功率、恢复率、人工接管率、
   检索拒绝率及越权事件数。
4. 建立试点租户、最小只读服务账户和可撤销凭据；禁止使用个人管理员令牌。

退出：试点负责人书面确认连接器、任务集、指标和数据处理边界。

## 1. 自助部署与诊断（第 1--2 周）

交付：

- 一个 `scripts/pilot_up.sh` 入口，生成最小配置、启动 Helm 依赖、执行迁移、
  创建应用角色，并输出 WebUI 地址；
- `scripts/pilot_check.py` 检查 PostgreSQL/pgvector、Redis、MinIO、模型路径、
  身份配置、迁移版本和连接器凭据，不打印密钥；
- 一个带样例数据的只读演示任务及 30 分钟快速开始文档；
- 版本化 `runs/{run_id}/manifest.json`，记录输入版本、配置摘要、代码提交、输出哈希。

验证：

- 空机器/干净命名空间从命令开始到首项样例任务不超过 30 分钟；
- 故意遗漏每项依赖时诊断给出可操作错误，不产生部分发布；
- 中断部署后重复运行保持幂等。

## 2. 单连接器与权限同步（第 2--4 周）

交付：

- 连接器契约：分页增量游标、源对象版本、删除墓碑、ACL 快照、重试分类和速率限制；
- PostgreSQL 中的连接器游标、同步运行、对象版本与失败记录；原始响应只进入受控
  MinIO 路径，索引仍只写 PostgreSQL；
- 将源 ACL 映射到 `document_acl`，权限收紧、删除或连接器撤销后立即撤回检索；
- 可重放同步：同一游标/事件不重复写入，不完整批次不推进游标。

验证：

- 新增、更新、删除、权限授予、权限撤销、网络中断和恢复各有集成测试；
- 两个 tenant、两个用户的正反权限矩阵中，未授权文档、记忆、缓存和工具输出均为零；
- 重复事件及重跑同步不产生重复文档、向量或外部副作用。

## 3. 生产工具网关（第 4--6 周）

交付：

- 每个工具声明输入 schema、作用域、只读/写入、所需角色、超时、重试预算、
  幂等键与审批策略；
- 统一网关在调用前注入身份和目标资源范围，调用后将参数摘要、结果摘要、审批、
  重试和失败写入 `agent_events`；
- 写入工具必须先进入 `waiting_approval`；批准可恢复执行，拒绝不产生副作用；
- 工具响应不得把无 ACL 的源内容或原始凭据写入任务、记忆、缓存或日志。

验证：

- 超时、限流、瞬时失败、重复投递、批准后恢复和拒绝均有故障注入；
- 相同幂等键重放的外部写入次数为 1；
- 越权调用在网关之前拒绝，并能按任务追溯审计事件。

## 4. 任务与记忆控制台（第 5--7 周）

交付：

- WebUI 展示任务计划、当前步骤、审批、重试、恢复、工具证据、输入/输出版本和成本；
- 记忆页展示来源事件、状态、ACL、有效期，更正与删除操作使用既有 Phase 2 API；
- 失败任务提供“安全重试”“从检查点恢复”“导出诊断”三个明确动作。

验证：

- 试点用户无需数据库访问即可定位失败原因、批准/拒绝操作并恢复一个可恢复任务；
- 任务和记忆页面分别执行正反权限测试；浏览器端不接收其他 tenant 的数据。

## 5. 资产发布、评测与运维（第 6--8 周）

交付：

- 连接器同步和任务结果的 manifest、哈希与原子 `current` 指针；
- 连接器质量集、工具故障集和端到端试点任务集；报告含完成率、成功率、恢复率、
  人工接管率、延迟和 ACL 拒绝；
- 将在线服务、连接器/ETL、训练和开发依赖拆分；WebUI 镜像不携带训练依赖；
- 备份恢复演练覆盖 PostgreSQL、必要 MinIO 原始对象和连接器游标。

验证：

- 不完整 manifest、哈希不符或失败同步不可成为 `current`；
- 删除/权限收紧后的检索回归为零；
- 恢复到隔离环境后能继续增量同步，且不会重复外部写入。

## 6. 真实试点与退出（第 9--12 周）

1. 两个团队各自运行四周，按周复盘指标和安全事件。
2. 每周至少抽样审计 10 个任务：证据来源、权限、工具审批、恢复和人工接管。
3. 仅在每周均无跨租户、越权工具或记忆泄漏事件时继续扩大使用。

最终退出门禁：

- 首项真实任务成功时间不超过 30 分钟；
- 连接器的新增、更新、删除、权限变更和失败恢复均可复现；
- 完成率、工具成功率、恢复率和人工接管率达到第 0 步签署的试点目标；
- 至少两个团队连续使用四周；
- 跨租户、越权工具及记忆泄漏事件为零；
- 所有 CI、连接器集成、故障注入、备份恢复和试点任务评测通过。

## 分支与提交策略

1. 从 `feat/phase-2-memory-governance` 创建
   `feat/phase-3-tooling-pilot`，不从 `main` 创建。
2. 以六个实施段分别提交：试点契约/部署、连接器、工具网关、控制台、资产与评测、
   试点证据。
3. 每段先通过本地与 pgvector 集成测试，再推送 PR；不要把客户凭据、原始数据或
   评测答案提交到仓库。
