# Phase 3 剩余工作执行计划

本计划基于已完成的 Git 游标、失败不推进、RLS、撤销删除、受控 `sync_git`
工具与基础部署诊断。P3-A 到 P3-D 的工程实现与本地验收已完成；最终 P3-E 仍是
真实试点门禁，不能用本地模拟替代。

## P3-A：完成 Git 内容与 ACL 同步

状态：已完成（文件正文、版本替换、删除同步、ACL 收紧及集成测试）。

目标：把 Git 提交/文件从“同步记录”变成受源权限约束的 PostgreSQL 文档。

1. 定义源对象字段：仓库、commit SHA、路径、blob SHA、提交时间、删除墓碑、
   可见主体 ACL 和源版本。
2. 扩展迁移：对象版本和 ACL 快照表；唯一键为 tenant + 源对象版本；运行记录关联
   已处理数量、跳过数量与失败类别。
3. Git API 分页读取提交及文件内容；原始响应写入受控 MinIO 路径，解析文本通过
   既有 `VectorStore.add_documents` 写入 PostgreSQL。
4. 将只读团队/用户 ACL 转换为 `document_acl`；权限收紧先撤销旧 ACL，再发布
   新版本。删除墓碑调用 `revoke_source`。
5. 明确错误类别：认证失败、限流、临时网络、源格式错误；仅临时错误重试，失败批次
   不推进游标。

验收：

- 新增、更新、删除、权限授予、权限撤销、分页、重放和网络中断各有 PostgreSQL
  集成测试；
- 两 tenant、两用户的正反矩阵中，未授权检索为零；
- 同一 commit/事件重放不产生重复文档、向量或 ACL；
- 撤销后 PostgreSQL 向量、FTS、Redis 缓存和工具结果均无可见内容。

## P3-B：完成自助部署和首项任务

状态：已完成（部署脚本、诊断和快速开始文档已交付；30 分钟目标待真实环境计时）。

目标：在干净环境中 30 分钟内完成一项只读任务。

1. 让 `pilot_up.sh` 生成最小 `.env` 模板、调用 Helm、等待 PostgreSQL/Redis/MinIO
   就绪、执行迁移并输出 WebUI 地址；所有步骤可重复执行。
2. 扩展 `pilot_check.py`：检查 pgvector、迁移、Redis、MinIO、模型路径、身份配置、
   Git 仓库和令牌存在性；只输出状态，不输出秘密。
3. 提供 `docs/PILOT_QUICKSTART.md`：只读 Git 服务账户、最小权限、样例仓库、
   同步、审批、查询、故障恢复和卸载。
4. 加一条演示任务：`sync_git` 经审批后同步，随后用 `rag_chat` 返回带来源的答案。

验收：

- 干净命名空间计时完成首任务 <= 30 分钟；
- 每项必需配置缺失时失败信息可操作且不写部分状态；
- 中断后重跑不重复同步、不重建已存在资源。

## P3-C：工具网关与控制台

状态：已完成（持久化工具网关的限流、脱敏、重试预算及 WebUI 任务/连接器/记忆面板）。

目标：将 Phase 2 API 转成可安全操作的试点产品面。

1. 扩展 `ToolSpec`：工具作用域、最大调用频率、重试预算和敏感字段清单；
   网关在事件中只写参数/结果摘要。
2. 对读工具注入身份与源范围；对写工具保持审批、幂等键和恢复语义。加入限流、
   超时、重试、批准后恢复、拒绝和重复投递的故障注入测试。
3. WebUI 增加任务控制台：计划、状态、当前步骤、审批、重试、恢复、事件、证据、
   成本与导出诊断。
4. WebUI 增加连接器页面：运行状态、游标摘要、失败类别、最近同步和重新同步入口。
   复用既有记忆 API 显示来源、ACL、有效期、更正和删除。

验收：

- 管理员可从 UI 恢复任务；普通用户只能看到自身 tenant 的任务、记忆和连接器；
- 任意越权工具调用在执行前拒绝；
- 同一写工具幂等键的外部副作用数为 1。

## P3-D：版本化资产、评测与运维

状态：已完成工程实现（manifest、五项工程任务集、恢复脚本、CI 评测和依赖分层文档）。

目标：让每次同步与任务结果可验证、可恢复、可比较。

1. 增加 `runs/{run_id}/manifest.json`：输入版本、配置摘要、代码提交、输出哈希、
   完成状态。仅成功且哈希完整的 run 可原子更新 `current`。
2. 编写三类评测：连接器 ACL/删除集、工具故障集、5--10 个端到端试点任务集。
3. 报告任务完成率、工具成功率、恢复率、人工接管率、延迟与 ACL 拒绝。
4. 分离在线、连接器/ETL、训练和开发依赖；确保 WebUI 镜像不安装训练栈。
5. 在隔离环境演练 PostgreSQL、必要 MinIO 原始对象、连接器游标和 manifest 恢复，
   并验证恢复后增量同步不重复写入。
6. 扩展 CI：pgvector 服务、连接器集成、故障注入、manifest 完整性、恢复、Helm
   渲染和所有评测。

验收：

- 不完整/哈希不符/失败 run 不能成为 `current`；
- 恢复环境可继续同步，且没有重复向量或重复工具副作用；
- CI 全绿并生成 Phase 3 退出报告。

## P3-E：真实试点与最终退出

状态：模拟预演已通过，真实试点未开始；后者是唯一阻止最终 Phase 3 退出的外部门禁。

### P3-E0：模拟试点预演（发布候选门禁）

`scripts/evaluate_phase3_pilot_rehearsal.py` 在两个隔离 tenant 中压缩执行四个周次：
每周每团队完成 10 个只读任务、一次审批写操作、一次故障恢复，并检查任务与源内容的
跨租户不可见性及每周审计事件。该预演通过后，Phase 3 状态为**发布候选**。

它不计入以下真实试点证据：真实团队采纳、长周期凭据/权限变动、人工接管质量与安全
事件。它们仍必须由 P3-E 的实际四周运行提供。

这是外部执行包，不能由代码或模拟替代。

1. 选定两个团队；每个团队提供 tenant、只读服务账户、任务集、成功阈值和安全联系人。
2. 连续四周运行；每周审计至少 10 个任务的 ACL、工具审批、来源证据、恢复与人工接管。
3. 每周复盘指标，任何跨租户、越权工具或记忆泄漏事件均停止扩大试点并进入修复。

最终签署条件：

- 首项真实任务 <= 30 分钟；
- 连接器生命周期与故障恢复可复现；
- 指标达到试点签署阈值；
- 两团队连续使用四周；
- 安全事件为零；
- P3-A 至 P3-D 的 CI、评测与恢复证据全部通过。
