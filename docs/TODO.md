# DataAlchemy 待办清单

> 本清单记录内部发布候选进入真实试点前仍需完成的产品工作。完成项应移入发布报告或归档，
> 不在此处累积历史记录。

## P0：智能体记忆与完整生命周期展示

- [ ] **Memory distillation**：在会话结束或达到轮数阈值时，从聊天事件提炼摘要、偏好、
  待办和程序性知识；每条记忆保留来源事件、tenant、置信度与有效期。
- [ ] **分级记忆写入策略**：会话摘要和低风险个人偏好可自动写入；跨用户、组织规则和
  高风险内容进入审批队列；密钥、权限、财务、人事等内容默认拒绝写入。
- [ ] **记忆冲突与用户控制**：写入前去重、冲突检测和 supersede；WebUI 支持查看来源、
  修改、删除、禁用自动记忆与设置保留期。
- [ ] **收紧记忆审批授权**：仅指定管理员可审批团队/高风险 candidate；不能让同 tenant
  的任意用户凭 memory ID 审批他人的候选。
- [ ] **生命周期演示**：在一个 `AgentRuntime` 任务中显示原始数据、Spark rough clean、
  refine/synthesis、文档/chunk、RAG 验证、反馈审核、记忆、训练候选、LoRA、评测和发布门禁。
  每阶段必须展示状态、输入/输出计数、产物/日志链接和失败原因。

## P1：试点数据与运行保障

- [ ] **受控 PDF/DOCX 试点路径**：沿 Spark 文档清洗进入完整生命周期；不绕过接入、
  脱敏、租户和审计门禁直接写入检索表。
- [ ] **隔离测试环境重置**：提供当前 Helm 路径的显式确认脚本，可选择清理专用测试
  PostgreSQL、MinIO 前缀、Redis 测试键和本地 k3d；默认不得触碰共享或生产资源。
- [ ] **运行产物可观测性**：将 Spark Job、训练 Job、评测报告和 adapter manifest 与任务
  事件关联，避免只显示 Kubernetes 注解或模糊的“completed”。

## P2：真实发布验收

- [ ] **GA-01 外部试点**：两支独立真实团队连续四周使用，完成周度审计、价值回顾和安全签署。
- [ ] **生产 OIDC 联调**：在目标 IdP、真实 tenant/role claim 与审计留存策略下完成验收。

## 验收原则

- 不以模拟成功代替 Spark、记忆、LoRA、评测或发布的真实运行结果。
- 自动记忆和 LoRA 发布均须可追溯、可撤销、tenant 隔离，并有明确的失败状态。
- `P0` 完成前，项目只能将单文档入库称为检索 smoke test，不能称为完整智能体试点。
