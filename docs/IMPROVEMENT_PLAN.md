# DataAlchemy 项目改进计划

> 修订日期：2026-07-29  
> 输入依据：[技术架构评估](./TECHNICAL_ARCHITECTURE_ASSESSMENT.md)、[产品评估](./PRODUCT_ASSESSMENT.md)、[原始 RoadMap](./DataAlchemy%20RoadMap.md)与[产品发展路线图](./PRODUCT_ROADMAP.md)  
> 执行假设：2～3 名全职工程人员；人员不足时顺延，不跳过阶段门禁

## 一、改进目标

本计划把当前功能丰富但编排固定的 PoC，演进为可安全试点的企业智能体。最终系统应具备四个可验证结果：

1. **安全**：用户、租户、文档、记忆、缓存和工具调用边界清晰。
2. **能行动**：智能体可以规划、调用工具、等待审批，并从检查点恢复。
3. **会记忆**：跨会话记忆有来源、有权限、有时效、可更正和可删除。
4. **可采用**：客户能在 30 分钟内完成部署并成功运行第一项真实任务。

北极星指标统一为：

> 每周由智能体成功完成、经用户确认有效且全程可追踪的企业任务数量。

## 二、现状校准

| 当前能力 | 确认状态 | 结论 | 本计划处理方式 |
| --- | --- | --- | --- |
| Coordinator/AgentManager | 固定流程原型 | 能编排步骤，但不是可重规划、可恢复的 Agent Runtime | 保留业务调用，外层增加统一任务状态和执行循环 |
| Agent A/B/C/D | 功能角色已存在 | 更接近检索、训练、评测和融合节点 | 封装为工具/节点，不继续扩张 Agent 数量 |
| 混合 RAG | 基础较完整 | CrossEncoder 是目标精排组件；FAISS/BM25/SQLite 不是最终存储 | Phase 2 直接收敛到 PostgreSQL + pgvector + PostgreSQL 全文检索 |
| Redis | 会话和缓存已使用 | 适合短期状态，不适合长期可治理事实 | 收缩为缓存、锁、队列和 TTL 工作记忆 |
| MinIO | 数据、索引和 LoRA 资产已使用 | 适合不可变大文件和产物 | 增加 manifest、哈希、版本和原子指针 |
| PostgreSQL + pgvector | 尚未形成统一底座 | 适合事件、检查点、画像、情景/程序记忆和权限 | 阶段 2 引入，不在安全与运行时边界明确前提前铺设 |
| WebUI | 登录、聊天、历史和反馈已有 | 可扩展为任务与审批界面 | 增加计划、工具、恢复、记忆管理，不重建前端 |
| 自动训练/反馈 | 有原型 | 缺少可信写入、评测和回滚 | 重新定义为受治理的可控学习 |

## 三、执行原则

1. **先运行时，后长期记忆**：没有稳定任务状态，记忆无法判断何时读、何时写。
2. **RAG 是语义记忆**：Phase 2 以 PostgreSQL + pgvector 与 PostgreSQL 全文检索作为唯一检索底座，保留 CrossEncoder 精排。
3. **Redis 退回基础设施角色**：只迁出长期事实，不为追求“零 Redis”制造风险。
4. **事件是事实，记忆是派生**：先追加不可变事件，再经过权限、PII、去重和冲突验证生成候选记忆。
5. **单智能体优先**：现有模块作为工具；只有基线证明必要时才增加多智能体。
6. **高风险动作必须审批**：写外部系统、训练、发布、删除和外发数据默认需要策略或人工批准。
7. **每项改进都有门禁**：代码、测试、指标、权限、失败恢复和回滚缺一不可。

## 四、阶段 0：安全与工程止血（第 1～4 周）

### 目标

建立不会泄漏、不会假成功、能够持续验证的最低运行基线，并准备智能体任务与记忆评测集。

| ID | 改进项 | 最小交付 | 验收标准 |
| --- | --- | --- | --- |
| SEC-01 | 会话所有权 | Session 保存 owner/tenant；HTTP、WebSocket、反馈统一鉴权 | 用户 A 无法读取或写入用户 B 会话 |
| SEC-02 | 缓存隔离 | key 加 tenant/user/model/index version；移除业务 `flushdb()` | 用户和版本之间无错误命中 |
| SEC-03 | 安全默认值 | 生产弱密钥、默认管理员或默认存储密码时 fail-fast | 仅显式开发模式可使用默认账户 |
| SEC-04 | 最小权限 | 移除不必要的 `privileged`，收缩 Kubernetes RBAC | 服务只保留必需权限 |
| PRIV-01 | 外发边界 | 纯本地/云增强模式、PII 检查和外发审计 | 纯本地无公网请求；云增强可追踪 |
| REL-01 | 失败传播 | 统一阶段结果；缺少必需产物时整项任务失败 | 各阶段故障注入均正确失败 |
| DATA-01 | 反馈可信度 | 默认 `unrated`；未审核反馈不得训练或写长期记忆 | 无隐式正样本或长期记忆 |
| INF-01 | 批处理正确性 | 按生成参数分组，或先取消复杂动态批处理 | 并发请求各自遵守参数 |
| ENG-01 | 工程入口 | 修复 CLI、语法和 Python 编译问题 | 核心命令 `--help` 与编译检查通过 |
| ENG-02 | 最小 CI | 编译、Ruff、pytest、Helm 和启动检查 | 每个 PR 自动执行并阻止失败合并 |
| ARCH-01 | 任务边界 | 定义目标、步骤、观察、工具结果、审批和终止字段 | 5～10 个真实任务能映射到同一状态模型 |
| EVAL-01 | 基线数据 | 真实任务集、20～50 个记忆问题和 RAG 基线 | 可重复输出质量、延迟、成本和失败原因 |

### 阶段退出门禁

- SEC-01～SEC-04、PRIV-01、REL-01 和 DATA-01 有自动测试；
- P0 安全问题为零，CI 稳定通过；
- 5～10 个真实任务和记忆评测集完成评审；
- 当前任务成功率、RAG 质量、延迟和成本已记录。

## 五、阶段 1：单智能体运行时（第 5～10 周）

> 开发分支：从 `feat/phase-0-security-baseline` 创建 `feat/phase-1-agent-runtime`，不直接从 `main` 创建；Phase 1 的 PR 先以 Phase 0 分支为基线，待 Phase 0 合并后再同步 `main`。

### 目标

用最小运行时让一个智能体可靠完成任务，不在本阶段引入多智能体、图数据库或第二套记忆框架。

| ID | 改进项 | 最小交付 | 验收标准 |
| --- | --- | --- | --- |
| AGT-01 | 任务状态模型 | 目标、计划、步骤、观察、审批、预算、版本和终止原因 | 所有任务使用一个权威状态 |
| AGT-02 | 执行循环 | `Plan → Act → Observe → Replan`、最大步数和明确终止 | 真实任务能重规划且不会无限循环 |
| AGT-03 | 检查点与恢复 | 每个关键步骤持久化；支持暂停、恢复和重试 | 服务重启后从最后安全点继续 |
| AGT-04 | Human-in-the-loop | 高风险工具执行前中断并等待批准 | 拒绝后不执行，批准记录可审计 |
| TOOL-01 | 工具注册表 | 名称、Schema、权限、超时、幂等键和结果限制 | 非法输入或未授权调用被阻止 |
| TOOL-02 | 现有能力工具化 | RAG、清洗、评测、训练和发布按优先级封装 | Agent A/B/C/D 不再形成第二套协调层 |
| OBS-01 | 不可变事件流 | 记录计划、观察、工具结果、审批和错误 | 任一任务可按事件完整回放 |
| UI-01 | 任务交互 | 展示计划、步骤、工具、审批、暂停恢复和失败原因 | 用户可理解并控制任务执行 |
| EVAL-02 | 任务基准 | 对 5～10 个真实任务测完成率、步骤数、工具成功率和接管率 | 结果可与固定流水线对比 |

### 框架选择

优先做两周 LangGraph 适配验证，只验证现有项目需要的四项能力：持久化、暂停恢复、Human-in-the-loop 和 FastAPI 集成。验证失败则保留最小自研状态机，不同时维护两个运行时。

> 2026-07-30 验证结论：LangGraph 0.6.11 的 `MemorySaver` 通过了中断恢复和异步调用探针，但不具备跨进程持久化；满足本项目要求需额外引入 durable checkpointer 与第二套状态存储。现有 SQLite Runtime 已覆盖四项能力，因此本阶段不采用 LangGraph。

### 阶段退出门禁

- 真实任务端到端完成且证据、审批和事件完整；
- 服务重启和工具暂时失败后可恢复；
- 未授权或未审批的高风险调用为零；
- 写工具具备幂等保护；
- 单智能体基线完成前，不开发多智能体。

## 六、阶段 2：分层记忆（第 11～18 周）

### 目标

直接以 PostgreSQL + pgvector 替换 FAISS、BM25 和 RAG SQLite 元数据，建立统一、可治理的检索、长期记忆和检查点底座。

| ID | 改进项 | 最小交付 | 验收标准 |
| --- | --- | --- | --- |
| MEM-01 | 持久化底座 | PostgreSQL + pgvector、迁移、备份、RLS | tenant/user scope 在数据库层生效 |
| MEM-02 | 事件事实源 | 追加式事件表，保存任务、工具、审批和来源 | 事件不可原地改写，可按任务回放 |
| MEM-03 | 统一记忆模型 | 工作、情景、语义、画像、程序五类；含来源、版本、状态和保留策略 | 每条长期记忆可追溯、可判定作用域 |
| MEM-04 | 可信写入门 | PII、ACL、去重、冲突和审批；candidate/approved/superseded/deleted | 未批准内容不会进入长期上下文 |
| MEM-05 | Memory Orchestrator | 按任务选择记忆、权限过滤、混合召回、重排和上下文预算 | 不相关或无权限记忆不进入 Prompt |
| RAG-01 | 语义检索收敛 | PostgreSQL FTS + pgvector + RRF，保留 CrossEncoder 与引用 | 唯一检索路径的质量、延迟和引用达到基线门槛 |
| MEM-06 | 直接切换验证 | 干净环境重建索引、离线评测、真实任务与备份恢复 | 不保留 FAISS/BM25/SQLite 兼容或双写路径 |
| REDIS-01 | Redis 收缩 | 只保留缓存、锁、队列和 TTL 工作记忆 | Redis 不再成为长期事实源 |
| MEM-07 | 生命周期 | 查看、更正、冲突替代、过期和级联删除 | 删除按 SLA 影响数据库、向量和缓存 |
| EVAL-03 | 记忆评测 | 召回正确率、错误/陈旧率、跨租户和任务增益 | 指标进入发布门禁 |

### 推荐数据边界

- **PostgreSQL + pgvector**：事件、检查点、情景/画像/程序记忆、文档、chunk、权限、向量和全文索引；唯一检索权威。
- **CrossEncoder**：对 PostgreSQL FTS 与 pgvector 的融合候选精排，保留引用质量。
- **Redis**：短期工作状态、缓存、锁和队列，全部有 scope 与 TTL。
- **MinIO**：文档、数据集、索引、模型和运行产物等不可变大文件。

### 阶段退出门禁

- 跨租户记忆召回为零；
- 每条记忆可追溯到事件、来源、版本和审批；
- 删除/遗忘可验证地覆盖数据库、向量与缓存；
- PostgreSQL 唯一路径在质量、延迟和运维上达到预先记录的门禁；
- 记忆系统对真实任务完成率产生可测的非负影响。

## 七、阶段 3：工具化试点（第 19～30 周）

### 目标

让目标客户能够自行部署、连接一个真实系统并完成第一项有价值任务。

| ID | 改进项 | 最小交付 | 验收标准 |
| --- | --- | --- | --- |
| DX-01 | 单机启动 | 一个默认命令、样例任务和自检 | 30 分钟内完成首项任务 |
| CONN-01 | 首个连接器 | 从 Jira、Confluence、Git 中按客户选择一个 | 覆盖增量、删除、权限变化和恢复 |
| TOOL-03 | 生产工具网关 | 读写策略、审批、超时、重试、幂等、速率和审计 | 重放不产生重复副作用 |
| ACL-01 | 权限贯通 | 源 ACL 进入检索、记忆、缓存和工具层 | 无权限用户不能间接获得内容 |
| UI-02 | 任务控制台 | 任务、计划、审批、恢复、证据和成本视图 | 用户可定位并恢复失败任务 |
| UI-03 | 记忆管理 | 查看、来源、更正、删除和保留策略 | 用户可控制其画像与长期记忆 |
| AST-01 | 版本化资产 | `runs/{run_id}`、manifest、哈希、原子 `current` | 不完整版本不能上线 |
| DEP-01 | 依赖收敛 | 在线、ETL、训练和开发依赖分开 | WebUI 不携带无关重依赖 |
| PILOT-01 | 真实试点 | 两个团队、约定任务和指标 | 连续使用四周，北极星指标增长 |

### 阶段退出门禁

- 首项任务成功时间不超过 30 分钟；
- 连接器的新增、更新、删除、权限和失败恢复可复现；
- 任务完成率、工具成功率、恢复率和人工接管率达到试点目标；
- 至少两个真实团队连续使用四周；
- 无跨租户、越权工具或记忆泄漏事件。

## 八、阶段 4：企业治理与可控学习

### 目标

把原始 RoadMap 的“可进化 LLM”落实为可验证、可审批、可停止和可回滚的持续优化。

| ID | 改进项 | 最小交付 | 验收标准 |
| --- | --- | --- | --- |
| IAM-01 | 企业身份 | SSO、RBAC、tenant 和工具策略 | 试点环境验收通过 |
| AUD-01 | 全链路审计 | 登录、检索、记忆、工具、外发、审批和发布日志 | 可按用户、任务和资源查询 |
| OPS-01 | 备份恢复 | PostgreSQL、MinIO、Redis、配置和版本指针 | 隔离环境恢复演练成功 |
| OPS-02 | SLO 与容量 | P50/P95、错误率、GPU、存储、成本和长稳测试 | 达到已公布目标，无数据损坏 |
| GOV-01 | 记忆治理 | 合并、衰减、冲突、过期、遗忘和保留策略 | 策略可回放、可解释、可回滚 |
| REL-02 | 安全发布 | 离线评测、影子、灰度、审批、晋级和自动回滚 | 连续两个发布周期无错误晋级 |
| ML-01 | 受控训练 | 仅已审核事件/反馈进入数据集，固定集对比 | 未提升的 LoRA 不发布 |

### 条件扩展

- 时间关系任务明确且 pgvector 无法满足时，再验证 Graphiti/Zep 类时序图记忆。
- 单智能体在分工、上下文或并发上出现可测瓶颈时，再验证多智能体。
- 单机处理或 Job/CronJob 无法达到真实规模目标时，再启用 Spark 或 Operator。

## 九、关键决策门禁

| 决策 | 通过条件 | 未通过处理 |
| --- | --- | --- |
| 采用 LangGraph | 持久化、HITL、恢复和集成验证通过 | 使用最小自研状态机 |
| 采用第三方记忆框架 | 两周对比在质量、治理或开发成本上明显胜出 | 使用 PostgreSQL + pgvector 最小方案 |
| 切换语义检索 | 干净环境评测、真实任务、删除和恢复均通过 | 不发布，不保留旧检索路径 |
| 移出 Redis 长期数据 | PostgreSQL 路径完成备份、删除和恢复验证 | Redis 仅保留 TTL 状态与缓存 |
| 引入图记忆 | 真实时序/关系任务显著受益 | 不增加图数据库 |
| 引入多智能体 | 单智能体基线显示明确瓶颈，收益覆盖成本 | 保持单智能体 + 工具 |
| 启用 LoRA | 固定评测集稳定优于 RAG/Prompt 基线 | 默认关闭 |
| 新连接器 | 有明确试点客户和验收指标 | 不提前建设 |

## 十、依赖关系与执行顺序

```text
安全/失败语义/评测基线
          ↓
单智能体运行时 → 工具契约 → 事件事实源
          ↓                    ↓
   持久检查点         分层记忆与可信写入
                              ↓
                    PostgreSQL 唯一路径门禁
                              ↓
                     单连接器真实试点
                              ↓
                    企业治理与可控学习
```

运行时状态和工具契约未稳定前，不开始长期记忆实现；PostgreSQL 唯一路径未通过离线评测、真实任务、删除和恢复门禁前，不发布；单智能体基线未完成前，不开发多智能体。

## 十一、前两周启动清单

1. 冻结新 Agent、图数据库、多连接器和未经过 Phase 2 门禁的 RAG/Redis 变更。
2. 把 SEC-01、SEC-02、REL-01、DATA-01 拆成可独立验收的 Issue。
3. 为跨用户会话、缓存污染、错误反馈和假成功补最小失败测试。
4. 修复 CLI 与编译基线，建立最小 CI。
5. 选定 5～10 个真实任务和 20～50 个记忆问题，记录当前结果。
6. 定义最小任务状态、工具契约和不可变事件字段。
7. 用一个只读 RAG 工具跑通 `Plan → Act → Observe → Replan` 最小闭环。
8. 明确哪些动作必须人工审批，哪些数据禁止外发。

两周结束时必须能回答：系统是否会越权、任务是否会假成功、智能体状态如何恢复、工具调用如何授权、哪些事件未来允许提炼为长期记忆。不能回答时，不进入数据库迁移和多工具开发。

## 十二、完成定义

任何改进项只有同时满足以下条件才算完成：

- 进入唯一生产路径，没有旁路式“支持”；
- 有一个缺陷复发时会失败的最小自动化测试；
- 失败可传播，写操作可重试且不产生重复副作用；
- tenant/user/文档/工具权限和数据外发边界明确；
- 任务、事件、记忆、工具结果和发布版本可追踪；
- 记忆可更正、过期和删除，派生向量与缓存同步失效；
- 涉及数据、索引、记忆或模型切换时具备影子验证和回滚路径；
- 能用任务、质量、安全、延迟或成本指标证明结果。
